2 · Loop da task Celery (executar_dominio_task)

  1. Lê EtlCheckpointDominio("professores") → captura token_antes
  2. Monta argumentos; adiciona --continuar se continuar_execucao=True
  3. Chama call_command("executar_dominio", --dominio professores, ...)
  4. Lê checkpoint novamente → captura token_depois
  5. linhas = max(token_depois − token_antes, 0)
  6. Se linhas < volume → para o loop; caso contrário define continuar_execucao = True e repete
  7. Em exceção → retry com continuar=True, countdown=60s, máx. 5 tentativas
Loop encerrado normalmente
  • linhas alteradas < volume no ciclo
  • retorna ok:{total_linhas_processadas}
Exceção → retry
  • salva checkpoint com situação = erro
  • próxima tentativa retoma com --continuar
  • após 5 falhas a task é abandonada

3 · Fluxo do comando etl_professores

  1. Se --continuar: lê checkpoint do domínio "professores".
    Se ultima_situacao == "erro" e 0 < ultima_fase < 4 → retoma da fase seguinte; caso contrário reinicia da fase 1.
  2. Cria id_execucao via RepositorioAuditoriaPostgres.iniciar_execucao("professores")
  3. Instancia EtlProfessoresService e chama servico.executar(fase_inicial)
  4. Para cada tabela no resultado: registra EtlExecucaoTabelaLida e EtlExecucaoTabelaEscrita com modo_escrita
  5. Calcula novo_token = token_anterior + total_alterado
  6. Atualiza EtlCheckpointDominio: ultima_pagina = ultima_fase_concluida, token_parada = novo_token, situacao = concluido
  7. Finaliza execução com situacao = "concluido"
Sucesso
  • checkpoint: situação = concluido
  • token_parada acumulado
  • ultima_pagina = fase concluída (4)
Erro
  • checkpoint: situação = erro
  • token_parada preservado do anterior
  • ultima_pagina = última fase bem-sucedida
  • exceção repropagada

6 · Checkpoint e retomada por fase

EtlCheckpointDominio — campos relevantes
dominio"professores"
ultimo_id_execucaoUUID da última execução
ultima_paginanº da última fase concluída (1, 2, 3 ou 4)
token_paradatotal acumulado de linhas alteradas
ultima_situacao"concluido" | "erro" | "em_execucao"
ultimo_sucesso_emdatetime do último sucesso
Lógica de retomada (--continuar)
  1. Lê checkpoint = obter_checkpoint_dominio("professores")
  2. Se ultima_situacao == "erro" e 0 < ultima_pagina < 4: fase_inicial = ultima_pagina + 1
  3. Caso contrário (sucesso ou sem checkpoint): fase_inicial = 1
  4. Em erro durante execução: salva checkpoint com ultima_pagina = servico.ultima_fase_concluida

7 · Modelos de auditoria (controle_auditoria)

EtlExecucao
db: etl_execucao
  • id_execucao UUIDField unique
  • dominio CharField(120)
  • situacao em_execucao · concluido · erro · cancelado
  • iniciado_em / finalizado_em DateTimeField
  • mensagem_erro TextField null
EtlExecucaoTabelaLida
db: etl_execucao_tabela_lida
  • id_execucao UUIDField (ref. EtlExecucao)
  • tabela_origem CharField(200)
  • numero_pagina IntegerField default=0
  • linhas_lidas IntegerField default=0
  • lido_em DateTimeField
EtlExecucaoTabelaEscrita
db: etl_execucao_tabela_escrita
  • id_execucao UUIDField (ref. EtlExecucao)
  • tabela_destino CharField(200)
  • linhas_escritas IntegerField default=0
  • modo_escrita "upsert" | "full_refresh"
  • escrito_em DateTimeField
EtlCheckpointDominio
db: etl_checkpoint_dominio
  • dominio CharField(120) unique
  • ultimo_id_execucao UUIDField null
  • ultima_pagina IntegerField (fase)
  • token_parada CharField(255) null
  • ultima_situacao CharField(30)
  • ultimo_sucesso_em DateTimeField null
EtlAuditoriaLinha
db: etl_auditoria_linha
  • id_destino CharField(255) PK
    "tabela:pk_origem"
  • hash_controle CharField(64) SHA-256 hex
  • atualizado_em DateTimeField
